and analysed how the methods in the `Die` and `Player` classes should behave. We also shared our individual notes and understanding of the overall game flow.

Individual contribution:

Initially, I used a while loop and try-catch block to validate the number of rounds. However, I placed the initial `scanner.nextInt()` outside the try-catch block. 
This caused the program to terminate unexpectedly when the user entered a string because the exception was not handled. I debugged the code by setting breakpoints to understand where the program was failing. 

After identifying the issue with the help of AI, I changed the logic by initializing numberOfRounds to 0 and moving the input statement inside the try-catch block within the while loop.
Initializing it to 0 ensures that the loop executes at least once, while the condition numberOfRounds <= 0 keeps asking the user until a positive integer is entered. 
The try-catch block handles non-numeric inputs, preventing the program from crashing.

After fixing the logic, I tested all input fields with valid and invalid values to ensure that users could re-enter valid inputs and continue playing without the program terminating unexpectedly.
